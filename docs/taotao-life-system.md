# 桃桃生活系统（第一阶段）

本目录的房间模板已接入 `taotao-life.js`，在原有单页房间体验上增加一套本地运行的角色生活模拟。

## 当前结构

- `index.html`：原有房间场景、时间/天气渲染、热点与抽屉；页面末尾加载桃桃模块。
- `taotao-life.js`：桃桃的需求状态、房间物品状态、行为决策、玩家互动、存档和状态面板。
- `sample-room.png`：原有房间底图，继续沿用。

## 桃桃的角色状态

| 字段 | 含义 | 变化方式 |
|---|---|---|
| hunger | 饥饿 | 随时间上升，吃饭/喂食下降 |
| energy | 精力 | 玩耍/探索消耗，睡觉恢复 |
| mood | 心情 | 陪玩、吃饭、休息可改善 |
| affection | 亲密度 | 摸摸/互动提升，随时间缓慢衰减 |
| hygiene | 整洁度 | 随时间下降，梳理毛发可恢复 |
| activity | 当前行为 | 由行为决策器或玩家互动设定 |
| location | 房间位置 | 映射到床、食盆、玩具、窗边、猫砂盆 |

## 房间状态

目前维护猫粮余量、饮水量、鲸鱼玩偶耐久、猫砂盆清洁度、床铺舒适度和窗边日照等数据。角色状态与房间状态一起保存在浏览器 localStorage 的 `whale-room-taotao-v1` 键中。

## 行为决策

`chooseAction()` 是一个可解释的优先级规则决策器，按饥饿、精力、亲密需求、卫生、心情和环境条件选择行为。决策结果通过 `setActivity()` 更新角色活动、位置、状态文案和生活日志。

当前行为：睡觉、吃饭、玩耍、探索、求摸摸、梳理毛发、发呆。

这不是云端大语言模型，也不会调用外部 AI 服务。它是可运行的本地生活模拟内核。后续可把 `chooseAction()` 替换为服务端模型调用，建议接口输入角色状态/房间状态/最近事件，输出结构化的 `{ id, why }`，并在服务端校验行为合法性。

## 玩家互动

- 喂食：消耗猫粮、降低饥饿。
- 摸摸：提升亲密度与心情。
- 陪玩：提升心情、消耗精力与玩具耐久。
- 添水：补满饮水。
- 清猫砂：恢复猫砂盆清洁度。
- 补给与修玩具：补满猫粮并修复玩具。

## 本地运行

1. 下载整个 `模板` 目录，确保 `index.html`、`taotao-life.js`、`sample-room.png` 在同一目录。
2. 用现代浏览器打开 `index.html`。若浏览器限制本地文件资源，可在该目录运行静态 HTTP 服务。
3. 页面下方会出现桃桃状态、房间状态、互动按钮和生活日志。
4. 存档仅在当前浏览器/设备有效；清理站点数据会清除存档。

## 下一阶段建议

1. 用独立角色 SVG/精灵图替换 emoji，并为行走、睡觉、进食、玩耍制作真正的状态动画。
2. 将角色位置映射到标注热点的几何区域，避免使用当前演示用的百分比坐标。
3. 将状态存档抽象成 repository，支持导入/导出 JSON，再按需迁移到 SQLite/后端。
4. 接入 LLM 行为规划时采用“规则保障 + 模型建议”：安全与生理需求由规则兜底，模型负责个性化选择和自然语言表达。
5. 增加行为冷却、事件去重、时间倍率、离线时间策略和可测试的模拟时钟。

## 已知限制

- 桃桃目前以 emoji 作为占位角色形象，位置是示意坐标，不是底图精确导航。
- 行为决策是本地规则模拟，不是 LLM。
- 没有账号同步、云端存档、真实天气 API 或后端服务。
- 需求变化按 5 秒轮询更新，离线补算最多按 180 分钟处理。
